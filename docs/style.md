# Style Guide: Notify Mini и Практика 3

Цель: единые правила для кода демо-сервиса подписок (lab/demo), тестов, коммитов и ответов ИИ-помощника.

## Область действия

- Код: `practices/practice_03/lab/demo/` (Python, стандартная библиотека).
- Сценарии практики: `practices/practice_03/lab/` (Makefile, experiment.py, Modelfile*).
- Документация для агентов: `AGENTS.md`, demo/AGENTS.md, skills в `.opencode/skills/`.

## Код (Python)

- PEP 8 (базово): имена функций и переменных в snake_case, строки ≤ 100 символов.
- Зависящие от окружения части (I/O, файлы) — простые и надёжные: проверка существования, атомарная запись.
- Исключения: явные и стабильные сообщения (например, `ValueError("empty name")`).
- Побочные эффекты минимальны и очевидны (чтение/запись рядом с модулем, без внешних зависимостей).
- Комментарии — только там, где поведение неочевидно. Докстроки краткие и по делу.
- Совместимость: стандартная библиотека Python 3.10+; не добавлять внешние зависимости.

Персистентность (demo/service.py):
- Формат хранения: JSON-массив строк.
- Чтение при старте, запись после изменения.
- Защита от порчи: при ошибке чтения начинать с пустого множества.
- Запись атомарно (через временный файл и replace).

## Тесты

- Фреймворк: стандартный `unittest`.
- Стиль: Arrange–Act–Assert, один аспект — один тест.
- Имена: `TestSomething.test_behavior`/`<Feature>Test.<case>`.
- Быстрота: без файловой/сетевой зависимости в юнит-тестах; побочные эффекты изолировать.

## Коммиты и PR

- Малые осмысленные изменения, один коммит — одна задача.
- Сообщения: `<area>: кратко и по сути` (напр. `demo: персистентность подписок через JSON`).
- Не включать секреты и локальные пути.
- Перед PR: `make test` зелёный, дифф понятен.

## Ответы ИИ-помощника (Notify Mini)

- Формат: короткий ответ по сути + основание `file:line`.
- Если данных нет: «В предоставленных материалах нет ответа».
- Нельзя выдумывать файлы, функции, CI/сервисы.
- Не выводить внутренние рассуждения; только финальный ответ.

Пример:
- Вопрос: «Как запустить тесты?» Ответ: `make test` (см. `practices/practice_03/lab/demo/README.md:6`).
- Вопрос: «Что при пустом имени?» Ответ: `ValueError("empty name")` (см. `demo/service.py:5–6`).

## OpenCode и агенты

- Build-агент выполняет команды в `practices/practice_03/lab/`, ведёт `REPORT.md`, складывает результаты в `lab/results/`.
- `local-guide` (demo) — read-only: разрешены `read/glob/grep`, запись и bash запрещены.
- MCP:
  - `filesystem-demo`: доступ только к `practices/practice_03/lab/demo` (read), для безопасной навигации.
  - `git`: операции и чтение метаданных репозитория.

## Документация

- Правила для агентов — в `AGENTS.md` (корень) и `practices/practice_03/lab/demo/AGENTS.md`.
- Skills — `.opencode/skills/<name>/SKILL.md`; описание что делает и когда применять.
