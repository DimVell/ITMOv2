# Практика 8 — Notify Mini

## Пользовательский сценарий

Владелец проекта открывает список подписчиков, вводит имя, отправляет форму и видит
сохранённую запись. При обновлении страницы список загружается из настоящего Python API.
Ошибки объясняются рядом с формой; введённый текст сохраняется для повторной попытки.

Реализация: [`lab/`](lab/). Инструкция: [`lab/README.md`](lab/README.md).
Исходное задание преподавателя в `README.md` сохранено.

## Макет и решения по дизайну

AI-инструмент — Codex. Для прототипирования использован самостоятельный HTML/CSS/JS-макет,
доступный без регистрации: [`lab/design/prototype.html`](lab/design/prototype.html).
В нём переключаются пять состояний: пустой список, ввод, загрузка, результат и ошибка.
Прототип не выдаёт демонстрационные данные за результаты настоящего API.

В условии практики не указан обязательный сервис: требуется выбранный инструмент
для макетов или прототипов и доступная ссылка либо экспорт результата. Здесь выбран
HTML/CSS/JS-прототип, созданный с помощью Codex. Figma не использовалась; её подключение
не является незавершённым обязательным этапом этой реализации.

Основные решения: белые карточки на светлом фоне, зелёный акцент, крупный заголовок,
форма слева и список справа. На узком экране карточки выстраиваются в одну колонку.
Счётчик показывает фактическое количество подписчиков; дополнительных функций,
которых нет в существующем API, интерфейс не обещает.

После прототипа в реализации уточнены состояния: отдельно обрабатываются загрузка
списка GET и отправка POST; ошибка списка имеет кнопку повторной загрузки, а ошибка
формы сохраняет точный ввод. Защита от повторной отправки есть и на кнопке, и в
обработчике submit. Дубликат показывается как информационный результат.

Библиотека компонентов — **Material UI**. Точные версии зафиксированы в `package-lock.json`.
Тема: [`lab/src/theme.ts`](lab/src/theme.ts), компоновка и фокус:
[`lab/src/styles.css`](lab/src/styles.css).

## Примеры заданий AI

Запрос пользователя: «переходить к 8 практике быстрее» в контексте прочитанных требований.
Рабочие формулировки для реализации:

1. Создать прототип управления подписчиками Notify Mini, показать пустое состояние,
   ввод, ожидание, результат и ошибку, предусмотреть мобильный экран.
2. Реализовать тот же сценарий на React с готовыми компонентами Material UI,
   общей темой и настоящими GET/POST `/api/subscribers` из практики 5.
3. Написать браузерные проверки видимого поведения: валидация, успешное добавление,
   пустой список, ошибки, задержка, дубликат, клавиатура и один POST во время ожидания.
4. Проверить сохранение после перезагрузки с настоящим API, затем временно сломать
   вывод ошибки и убедиться, что соответствующий тест обнаруживает регрессию.

Эти формулировки описывают рабочие задания AI; они не являются утверждением о том,
что пользователь вручную вводил каждый из этих запросов в отдельный сервис.

Проверка результата AI: TypeScript выявил несовместимое свойство типографики с Material UI 9;
настройка перенесена в `sx`. Настроены изолированные данные тестового API и проверка
ошибок по реальному JSON-контракту. Личные данные приложения не используются тестами.
Прототип и итоговый интерфейс нужно также просмотреть человеку перед защитой.

## Проверки и доказательства

Команды запускаются из `lab/`:

```bash
npm test
npm run build
npm run evidence
```

Набор из 16 браузерных тестов находится в
[`lab/tests/subscribers.spec.ts`](lab/tests/subscribers.spec.ts).
Проверяются компоненты и действия пользователя, сообщения ошибок, сохранение ввода,
пустой ответ, задержка, обрыв сети, дубликат, двойной клик и Enter, мобильные размеры
375px/320px и видимый клавиатурный фокус. Один тест выполняет полный сценарий с
настоящим Python API без перехвата запросов.

Результат последнего запуска и источник данных каждого скриншота:
[`evidence/verification.json`](evidence/verification.json).
Снимки: [пустое состояние](evidence/empty.png), [ввод](evidence/input.png),
[загрузка](evidence/loading.png), [успех](evidence/success.png), [ошибка](evidence/error.png),
[настоящий API после перезагрузки](evidence/real-api.png),
[мобильный экран](evidence/mobile.png), [прототип](evidence/prototype.png).

Проверка чувствительности тестов: временно скрывается текст ошибки POST в `App.tsx`,
запускается тест «ошибка POST сохраняет ввод и позволяет повторить попытку», затем
восстанавливается исходник и весь набор тестов запускается повторно.
Фактический результат этой проверки записывается в `evidence/mutation-check.json`.

## Соответствие критериям

| Критерий | Артефакт / проверка |
|---|---|
| AI-макет | HTML-прототип с переключением состояний, исходник и снимок |
| Библиотека компонентов | Material UI в `src/App.tsx` |
| Единый стиль | `theme.ts`, общая типографика, цвета и отступы |
| Полный сценарий | POST в настоящий API, запись в списке, проверка после reload |
| Соответствие прототипу | Те же блоки, тексты, палитра, компоновка и состояния |
| Доступность | Label поля, skip link, keyboard-тест, видимый фокус |
| Защита от повторов | Тест считает запросы при двойном клике и повторном submit |
| Компоненты и взаимодействия | Отображение списка, ввод, отправка и повторная загрузка |
| Валидация | Пустая строка, пробелы и имя длиннее 40 символов |
| Состояния | Пусто, загрузка, успех, ошибка; тестовые ответы соответствуют API |
| Сквозной клиентский тест | Добавление через форму до видимого результата |

## Демонстрация

1. Выполнить `npm start` в `lab/` и открыть адрес из терминала.
2. Открыть прототип `/design/prototype.html` и показать его состояния.
3. В приложении добавить имя, обновить страницу и показать сохранённую запись.
4. Ввести пустое и слишком длинное имя, показать доступность с клавиатуры и мобильный вид.
5. Выполнить `npm test`, открыть `npm run test:report` и показать проверку двойной отправки.
6. Показать `verification.json` и результат временного нарушения поведения.

Исходный код и клиентские тесты: [ветка practice-08 в репозитории DimVell/ITMOv2](https://github.com/DimVell/ITMOv2/tree/practice-08/practices/practice_08).
