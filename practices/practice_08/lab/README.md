# Notify Mini — практика 8

Работающий фронтенд управления подписчиками: AI-прототип → React-интерфейс на
Material UI → существующий Python API → браузерные проверки.

Пользователь — владелец небольшого проекта. Он открывает список, вводит имя,
добавляет подписчика и видит результат. Запись сохраняется после обновления страницы.
Новая реализация находится в этой папке; сервер и правила подписчиков переиспользуются
из `practices/practice_05/app`.

## Запуск

Нужны Python 3.10+ и Node.js 22.12+ (проверено с Node.js 26.10.0).
Рабочая папка для всех следующих команд — `practices/practice_08/lab`.

```bash
npm ci
```

Запуск API и интерфейса одной командой:

```bash
npm start
```

Остановка обоих процессов — `Ctrl+C`. Для раздельного запуска в первом терминале:

```bash
npm run api
```

Во втором:

```bash
npm run dev
```

Приложение: <http://127.0.0.1:5173>.
Прототип: <http://127.0.0.1:5173/design/prototype.html>.
Данные приложения: `.data/subscribers.json`. Пустой файл создавать не нужно.
API по умолчанию запускается на `127.0.0.1:8000`; Vite проксирует `/api` на этот адрес.
При другом порте задайте `NOTIFY_API_TARGET` перед запуском Vite.

## Макет, компоненты и интеграция

AI-инструмент: Codex. Доступный для проверки экспорт прототипа —
[`design/prototype.html`](design/prototype.html), его можно открыть как отдельный файл.
Переключатели показывают пустое состояние, ввод, загрузку, результат и ошибку.

Выбранная библиотека — **Material UI**. Переиспользуются `Button`, `TextField`, `Card`,
`Alert`, `Avatar`, `Chip`, `List`, `Skeleton`, `CircularProgress` и компоненты типографики.
Цвета, типографика, радиусы и общие настройки компонентов заданы в
[`src/theme.ts`](src/theme.ts), адаптивная компоновка и фокус — в
[`src/styles.css`](src/styles.css).

Настоящий API:

- `GET /api/subscribers` → `{"subscribers":[{"name":"Анна"}],"count":1}`.
- `POST /api/subscribers` с `{"name":"Анна"}` →
  `{"subscriber":{"name":"Анна"},"created":true}`.
- Для дубликата `created:false`; ошибка — `{"error":{"code":"…","message":"…"}}`.

Имя обязательно, после нормализации не длиннее 40 символов. На клиенте показывается
ранняя проверка, окончательное решение принимает существующий сервер. Во время POST
блокируются поле и кнопка, а синхронный флаг в обработчике защищает от повторного
submit, включая Enter. При ошибке введённый текст сохраняется и можно повторить запрос.
Список можно повторно загрузить после ошибки GET. Действия доступны с клавиатуры,
есть подписи полей, видимый фокус и сообщения `alert`/`status`.

## Проверки

Первичная установка браузера:

```bash
npx playwright install chromium
```

Все клиентские тесты и проверка сборки:

```bash
npm test
npm run build
```

Тесты самостоятельно запускают Vite и реальный Python API с временным файлом данных.
API-тестовый порт — 8108, фронтенд — 5178. Сохранённые данные приложения не используются.
Основная часть проверок подменяет API через Playwright: успешный и пустой ответ,
задержка, ошибки GET/POST, обрыв сети и некорректный ответ. Один отдельный браузерный
тест без подмены добавляет запись в настоящий API и проверяет её после перезагрузки.

Проверяются видимые результаты, а не наличие компонентов в исходниках. Отдельный тест
считает POST-запросы при двойном клике и Enter во время ожидания. Есть проверки
мобильного экрана 375px, длинного имени при 320px и клавиатурной отправки с фокусом.

HTML-отчёт тестов:

```bash
npm run test:report
```

Скриншоты всех состояний, мобильного интерфейса и работы с настоящим API:

```bash
npm run evidence
```

Результаты помещаются в `../evidence/`. В `verification.json` указано, какие снимки
используют тестовые ответы, а какие — настоящий API. Доказательство проверки качества
тестов описано в [`../REPORT.md`](../REPORT.md).
