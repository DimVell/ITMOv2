# Requirements: subscriber logic

## User story

Как сервис Notify Mini, я хочу валидировать и хранить уникальных подписчиков через стабильный
HTTP API, чтобы UI получал однозначный результат для создания, повтора и ошибки.

## Acceptance criteria

1. WHEN корректное новое имя отправлено, THE API SHALL нормализовать его, сохранить и
   вернуть `201` с `created=true`.
2. WHEN эквивалентное имя уже существует, THE API SHALL не создавать запись и вернуть `200`
   с `created=false` и исходным написанием.
3. IF имя пусто, не является строкой или длиннее 40 символов, THE API SHALL вернуть `400`
   с `error.code=invalid_name`.
4. IF JSON повреждён или не является объектом, THE API SHALL вернуть `400` с
   `error.code=invalid_json`.
5. WHEN список запрошен, THE API SHALL вернуть все имена в детерминированном порядке и
   согласованный `count`.
6. WHEN настроен data file, THE LOGIC SHALL атомарно сохранять список и загрузить его при
   следующем запуске.
7. THE LOGIC SHALL не изменять исходный demo практики 3.

## Out of scope

Удаление, конкурентное распределённое хранилище, аутентификация и миграция повреждённого JSON.
