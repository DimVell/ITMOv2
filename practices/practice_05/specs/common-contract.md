# Общий контракт UI ↔ logic

## Нормализация и инварианты

1. `name` — строка после удаления крайних пробелов и схлопывания внутренних пробелов.
2. Длина нормализованного имени — от 1 до 40 Unicode-символов.
3. Уникальность регистронезависимая; сохраняется написание первого добавления.
4. Список сортируется по имени без учёта регистра.

## `GET /api/subscribers`

Успех `200`:

```json
{
  "subscribers": [{"name": "Ann"}],
  "count": 1
}
```

## `POST /api/subscribers`

Запрос:

```json
{"name": "  Ann  "}
```

Новое имя — `201`; существующее после нормализации — `200`:

```json
{
  "subscriber": {"name": "Ann"},
  "created": true
}
```

Для повтора `created` равен `false`, а `subscriber.name` содержит исходное сохранённое имя.

Неверное имя или JSON — `400`:

```json
{
  "error": {
    "code": "invalid_name",
    "message": "Введите имя подписчика."
  }
}
```

Допустимые коды: `invalid_name`, `invalid_json`, `invalid_body`, `payload_too_large`,
`not_found`. UI обязан зависеть от `message` для текста и может использовать `code` для
сценария; неизвестный код не должен ломать страницу.
