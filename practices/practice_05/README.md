# Домашняя работа 5: две команды — одна фича

Реализована третья User Story учебного Notify Mini: веб-управление подписчиками. Так как
backlog практик 1–2 в репозитории не заполнен, история восстановлена из существующего
поведения `practice_03/lab/demo`: непустое имя добавляется, дубликат не создаёт вторую запись.
Оригинальный demo не изменён.

Для ДЗ выбран **Kiro** — другой SDD-framework из лекции. OpenSpec используется только как
точка сравнения в [`COMPARISON.md`](COMPARISON.md), что соответствует условию задания.

## Запуск

Нужен только Python 3.10+.

```bash
cd practices/practice_05
make test
make demo
make run
```

После `make run` страница доступна по `http://127.0.0.1:8000`. Локальные данные сохраняются
в `.data/subscribers.json`; каталог исключён из Git.

## Условия приёмки

- Новое нормализованное имя появляется в списке и переживает перезапуск.
- Повтор с другим регистром не создаёт дубликат и не показывается как ошибка.
- Пустое, нестроковое и более длинное 40 символов имя отклоняется с понятной ошибкой.
- UI отображает загрузку, пустое состояние, успех, дубликат и ошибку.
- Старое правило Notify Mini «непустое имя + отсутствие дубликатов» сохранено.

## Границы

Удаление, редактирование, авторизация и рассылка не реализуются. Эти функции не нужны для
одной согласованной истории и увеличили бы SDD-overhead, о котором предупреждает лекция.
