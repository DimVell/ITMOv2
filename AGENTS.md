# AGENTS: инструкции, контекст и правила

Документ описывает, как работают агенты для учебного проекта `lab/demo`:

- Зачем и что им разрешено
- Какой контекст им доступен
- Как запускать проверки и что считается корректным ответом

Файл служит для передачи инструкций, контекста и правил работы ИИ-помощников в рамках практики 3. Он дополняет `opencode.json` и `repo-system.txt`.

## Маршрут (где и как запускать)

- Рабочая директория агента-помощника (read-only): `practices/practice_03/lab/demo`
- Рабочая директория Build-агента (исполняет команды): `practices/practice_03/lab`
- База локального API Ollama: `http://localhost:11434/v1`

Команда проверки чтения (read-only агент):

```
opencode run --dir demo \
  --agent local-guide \
  --model ollama/itmo-agent \
  --format json \
  "Прочитай README.md инструментом read. Назови команду тестирования со ссылкой на файл"
```

Образ модели для локального помощника: создаётся из `Modelfile.agent` как `itmo-agent` (контекст 65536).

## Агент: local-guide (read-only)

- Назначение: читать файлы учебного репозитория `demo/` и отвечать по предоставленному контексту.
- Инструкции (system): берутся из файла `repo-system.txt` через `prompt": "{file:./repo-system.txt}"`.
- Права (см. `opencode.json`):
  - `read`: allow
  - `glob`: allow
  - `grep`: allow
  - Любые другие инструменты: deny
- Модель и лимиты: `ollama/itmo-agent`, context 65536, output 4096.
- Запрещено:
  - Запись в файлы, выполнение команд, сеть и внешние плагины.
  - Выдумывать файлы, функции, CI/сервисы.
- Формат ответа:
  - Короткий ответ по сути.
  - Обязательно привести основание с указанием `file:line` из прочитанного контекста.
  - Если данных нет, ответ: «В предоставленных материалах нет ответа».

Пример запроса:

```
Прочитай README.md инструментом read. Назови команду тестирования со ссылкой на файл
```

Ожидаемый ответ (пример):

```
Команда тестирования: make test (см. demo/README.md:6)
```

## Агент: Build (рабочая сессия)

- Назначение: создаёт конфигурации, выполняет команды из `practices/practice_03/lab/`, сохраняет результаты в `lab/results/` и ведёт `REPORT.md`.
- Права: может изменять `REPORT.md`, `lab/results/` и конфигурации практики. Входные файлы `lab/demo/` при сравнении не меняет.
- Обязанности:
  - Подготовить локальную модель через Ollama (`itmo-local`, `itmo-agent`).
  - Выполнить эксперименты baseline/system и температурные прогоны.
  - Замерять метрики (`wall_seconds`, `load_seconds`, `total_seconds`, `decode_tokens_per_second`).
  - Запускать `opencode run` для вопросов из `lab/QUESTIONS.md` отдельными сессиями.
  - Не передавать тестируемой модели эталоны и отчёт.

## Контекст и модели

- Базовая модель: `qwen3.5:4b` (Q4_K_M), формат `gguf`, family `qwen35`.
- Локальные образы:
  - `itmo-local`: Modelfile, контекст 4096, temperature 0.2 (эксперименты API).
  - `itmo-agent`: Modelfile.agent, контекст 65536 (для OpenCode).
- Настройки по умолчанию (эксперименты): `temperature=0.2`, `seed=42`, `think=false`, `num_ctx=4096` (для API-скрипта), `num_predict=512`.

## Диагностика и безопасность

- Проверка Ollama API:
  - `curl --fail http://localhost:11434/api/tags`
  - `ollama list` / `ollama show itmo-agent` / `ollama ps`
- Если `opencode run` зависает:
  - Запустить с логами: `OPENCODE_LOG_LEVEL=debug opencode run ...`
  - Проверить глобальные настройки OpenCode и отключение внешних MCP/провайдеров.
  - Убедиться, что `baseURL` указывает на локальный endpoint и Ollama доступен.
- Политика безопасности:
  - Не хранить и не передавать секреты; не выводить внутренние рассуждения.
  - Текст ответа и события инструментов сохраняются; внутренние размышления не записываются.

## Эталоны и проверка ответов

- Эталоны формируются Build-агентом по коду `demo/` и не передаются в сессии `local-guide`.
- Сопоставление ответов с кодом: обязательна ссылка `file:line`.
- Вопрос без ответа в репозитории должен быть явно признан как «нет данных».
